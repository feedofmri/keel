04 / DECIDE

A calibrated line, then a labelled PR.

The threshold comes from held-out bug fixes and the risk level you picked. Below it: AUTO-MERGE. Above it: NEEDS REVIEW, with the reasons written out for the reviewer.

Meta models, three jobs

Not one chat call. A panel of models that check each other.

Muse Spark

Meta Model API

Writes the main candidate patches, then switches sides and writes the adversarial tests that attack them. It also writes the plain-English explanation on the PR.

Muse Spark Open

open weights · meta-models/muse-spark-open-1026

A second, independent generator, and a window into its own confidence. Token logprobs and reasoning length become uncertainty features. Closed APIs can't give you that.

Muse Glimmer

open weights · optional

Cheap triage: estimates how hard a bug is and sets the sampling budget, so easy fixes don't burn the expensive model's tokens. It's also the cost baseline in the evaluation.

The guarantee

A bound you can write into policy.

Pick α. Keel finds the largest threshold its held-out bugs can support, and the error stays under α. Naive rules don't.

CRC: per bug (default)

λ̂ = max{ λ : (Σᵢ wrongᵢ·1[sᵢ ≤ λ] + 1)/(n+1) ≤ α }

On average, at most α of bugs end up with a wrong patch auto-merged. No assumptions about the model.

LTT: per merge

Each threshold on a fixed grid passes an exact binomial test. With probability ≥ 1−δ, at most α of auto-merged patches are wrong.

Exchangeable bugsSame models, prompts and kind of repo as calibration. Keel fingerprints its configuration and refuses a stale calibration.
On averageThe guarantee covers bugs in aggregate, not one particular patch.
Hidden tests“Correct” means passing tests the agent never saw. That's stronger than “passes its own tests”.
Safe defaultWith no calibration data, Keel never auto-merges. Everything goes to review.
