The code-repair agent that knows when it shouldn't be trusted.

Coding agents write plausible patches faster than anyone can review them. Keel lets Meta's Muse models fix your failing tests, then uses conformal risk control to decide which fixes are safe to merge on their own, with a statistical guarantee on how often it's wrong.

The problem

Generation isn't the bottleneck any more. Review is.

“Tests pass”

isn't proof. Agents overfit the visible tests, special-case inputs, or quietly edit the tests themselves.

Confidence

scores from the model aren't calibrated. "90% sure" is not 90% right, and you can't set a policy on it.

Every PR

still lands on a human, so the time agents save in writing code comes back as review load.

How it works

Meta models propose, cross-examine, and Keel decides.

Every step runs in a throwaway sandbox. Secrets are scrubbed from the environment of any code a model wrote.

Reproduce

Run the test suite, find the failing tests and the code their tracebacks point to.

your CI

Generate

Sample several candidate patches from two Meta models for diversity. Muse Spark Open also reports token log-probabilities, a confidence signal only open weights expose.

Muse Spark + Muse Spark Open

Attack

Muse Spark reads all the candidates and writes new tests aimed at where they disagree. Patches that only fit the visible tests fall here.

Muse Spark

Score

A code-aware nonconformity score combines test outcomes, adversarial survival, diff size and locality, static-analysis deltas, agreement across samples and models, and model uncertainty. Edits to tests are hard-blocked.

Keel

Decide

A threshold calibrated on held-out bug fixes turns the score into AUTO-MERGE or NEEDS REVIEW, at the risk level you chose. The PR explains why.

conformal risk control
The guarantee

A bound you can set as policy, not a vibe.

CRC: per bug (default)

Pick α, say 10%. Keel chooses the largest threshold λ̂ whose adjusted error on n held-out bugs stays under α:

λ̂ = max { λ : (Σᵢ wrongᵢ·1[sᵢ ≤ λ] + 1) / (n + 1) ≤ α }

Then, on average, at most α of bugs end up with a wrong patch auto-merged. No assumptions about the model or the data distribution are needed.

LTT: per merge

Prefer a bound on the share of auto-merged patches that are wrong? Learn-then-Test tests every threshold on a fixed grid with an exact binomial test, and keeps only the ones it can certify.

Then, with probability at least 1 − δ, at most α of auto-merged patches are wrong. It's stricter, so it needs more calibration data before it merges anything.

The fine print

Assumes
new bugs are exchangeable with the calibration bugs: same models, prompts and kind of repository. Keel fingerprints its configuration and refuses to auto-merge on a stale calibration.
Means
a guarantee on average over bugs, not a promise about one particular patch.
“Correct”
means passing held-out tests the agent never saw, which is stronger than “passes the tests it was given”, but still not a proof.
Default
with no calibration data, Keel never auto-merges. Everything goes to review.
Evaluation

Measured, not promised.

Keel is evaluated on SWE-bench Lite and QuixBugs with a visible/hidden test split, over hundreds of random calibration/test splits. It's compared with merging whenever tests pass, with model self-confidence, and with its own score without calibration.

Install

One workflow file.

Keel runs as a GitHub Action on GitHub's own runners. It triggers when CI fails or when someone with write access comments /keel fix, then opens a labelled pull request.

name: Keel
on:
  workflow_run: { workflows: [CI], types: [completed] }
  issue_comment: { types: [created] }
permissions: { contents: write, pull-requests: write, issues: write }
jobs:
  keel:
    if: github.event_name != 'workflow_run' || github.event.workflow_run.conclusion == 'failure'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { ref: "${{ github.event.workflow_run.head_sha || github.ref }}" }
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install -e . pytest
      - uses: feedofmri/keel@v1
        env:
          KEEL_MUSE_SPARK_API_KEY: ${{ secrets.KEEL_MUSE_SPARK_API_KEY }}
          KEEL_SPARK_OPEN_API_KEY: ${{ secrets.KEEL_SPARK_OPEN_API_KEY }}
        with: { calibration: .keel/calibration.json, alpha: "0.1" }

Full example: examples/workflows/keel.yml. Or run it locally: pip install git+https://github.com/feedofmri/keel && keel repair --repo .
